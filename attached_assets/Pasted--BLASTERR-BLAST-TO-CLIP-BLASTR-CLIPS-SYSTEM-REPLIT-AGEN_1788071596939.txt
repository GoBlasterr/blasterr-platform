# BLASTERR — BLAST-TO-CLIP / BLASTR CLIPS SYSTEM

## REPLIT AGENT BUILD PROMPT

Build a new major feature inside the BLASTERR social platform called:

# 🔥 BLASTR CLIPS

The purpose of BLASTR CLIPS is to turn compelling BLASTERR posts into short-form vertical videos that users can export and share to platforms such as:

* YouTube Shorts
* TikTok
* Instagram Reels
* Facebook Reels
* X

This feature should become BLASTERR's built-in content distribution and marketing engine.

---

# 1. CORE CONCEPT

When a user creates a particularly interesting, funny, controversial, dramatic, informative, or entertaining Blast, they should have a prominent button:

# ✨ CREATE CLIP

The user clicks:

### CREATE CLIP

BLASTERR opens a professional short-form video creation interface.

The user selects a video style:

🔥 **BREAKING BLAST**

😂 **FUNNY**

🚨 **DRAMATIC**

🧾 **RECEIPTS**

⚔️ **DEBATE**

🎤 **STORY**

Then BLASTERR automatically creates a vertical:

# 9:16 BLASTR CLIP

The generated video should contain:

* Original Blast content
* User/profile attribution
* BLASTERR branding
* BLASTR CLIPS branding
* Animated captions
* Appropriate background visuals
* Optional uploaded media from the original Blast
* Optional audio/music from an approved/licensed library
* Dynamic transitions
* CTA
* BLASTERR logo
* BLASTERR website/app branding

The final video should be optimized for short-form social media.

# 29. IMPORTANT — SOCIAL PLATFORM INTEGRATIONS

Do not fake direct publishing integrations.

Different social platforms have different APIs, OAuth requirements, upload requirements, account permissions, and review processes.

Build the architecture so each platform is an independent integration.

Example:

```text
SocialDistributionService
    ├── YouTubeService
    ├── TikTokService
    ├── InstagramService
    ├── FacebookService
    └── XService
```

Initially implement:

### EXPORT VIDEO

### COPY SHARE LINK

### NATIVE WEB/MOBILE SHARE

Where official APIs and permissions are available, build OAuth-based integrations.

Do not scrape websites.

Do not automate browser actions to bypass platform restrictions.

Do not store third-party passwords.

# 46. RENDER QUEUE

Do not render videos synchronously inside a normal page request.

Create an asynchronous rendering architecture.

Example:

```text
User clicks CREATE CLIP
        ↓
Create clip record
        ↓
Queue render job
        ↓
Render worker
        ↓
Generate video
        ↓
Upload video
        ↓
Generate thumbnail
        ↓
Update clip status
        ↓
Notify user
```

Statuses:

### DRAFT

### QUEUED

### PROCESSING

### COMPLETED

### FAILED

Allow users to retry failed renders.
