# REPLIT AGENT PROMPT — BLASTERR ADMIN CONTROL CENTER

Build a completely separate, secure **BLASTERR ADMIN** web application that serves as the centralized administration and moderation control center for my existing **BLASTERR** social platform.

## IMPORTANT

This is **NOT a redesign of the existing BLASTERR platform**.

Do not modify the existing public BLASTERR user interface unless specifically required to connect an admin-controlled feature.

The goal is to create a separate admin website that connects to the **existing BLASTERR backend, database, authentication system, users, posts, comments, reports, notifications, and other platform data**.

The Admin site should be accessible through a separate admin URL/domain such as:

**admin.blasterr.com**

The admin dashboard should be completely inaccessible to normal BLASTERR users.

* Target
* Reason

# 19. SECURITY

Treat the Admin application as a high-security system.

Implement:

* Separate admin authentication
* Role-based access control
* Secure sessions
* Session expiration
* Password protection
* Optional 2FA architecture
* Rate limiting
* CSRF protection
* Input validation
* Server-side authorization
* Secure API endpoints
* Audit logging

CRITICAL:

Do not rely on hiding admin buttons for security.

Every administrative action must be authorized on the server.

A normal BLASTERR user must NEVER be able to call an admin API endpoint successfully.

# 31. DEVELOPMENT REQUIREMENTS

Before writing major code:

1. Inspect the existing BLASTERR application.
2. Identify its framework.
3. Identify its database.
4. Identify its authentication.
5. Identify its API architecture.
6. Identify the existing user/content schemas.
7. Identify existing environment variables.
8. Identify existing storage.
9. Determine the safest way for the Admin application to communicate with the existing BLASTERR backend.

DO NOT break the existing BLASTERR application.

DO NOT replace existing authentication unless necessary.

DO NOT duplicate existing platform data.

DO NOT create fake production statistics.

If something is not yet implemented in BLASTERR, clearly label the Admin feature as requiring backend integration rather than pretending it works.
