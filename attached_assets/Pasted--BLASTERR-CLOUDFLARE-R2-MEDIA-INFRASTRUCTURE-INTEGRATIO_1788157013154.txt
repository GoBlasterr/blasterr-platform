# BLASTERR — CLOUDFLARE R2 MEDIA INFRASTRUCTURE INTEGRATION

You are working on the BLASTERR social media platform.

I have already created a **Cloudflare R2 account** and want BLASTERR to use Cloudflare R2 as its dedicated media-storage infrastructure.

## IMPORTANT ARCHITECTURE

Do NOT replace Supabase.

Use:

### SUPABASE

Primary application database and authentication.

Store:

* Users
* Profiles
* Blasts
* Comments
* Reactions
* Followers
* Targets
* Notifications
* Reports
* Clip metadata
* Media metadata
* Permissions
* Analytics

### CLOUDFLARE R2

Dedicated object/media storage.

Store:

* User-uploaded images
* Blast images
* User-uploaded videos
* Blast videos
* Profile images
* Cover images
* Thumbnails
* BLASTR Clips
* Generated video files
* Other large media assets

# 8. SECURE UPLOAD SYSTEM

Build a secure server-side upload workflow.

Users should NOT receive the R2 secret keys.

Preferred architecture:

```text
USER
 ↓
BLASTERR
 ↓
Secure upload authorization
 ↓
R2
```

Where appropriate, use signed/presigned upload URLs so large media can upload directly to R2 without unnecessarily routing the entire file through the application server.

This is important for scalability.

---

# 9. PRESIGNED UPLOADS

Implement a secure mechanism for generating presigned upload URLs.

Example flow:

```text
User selects image/video
        ↓
BLASTERR requests upload authorization
        ↓
Server validates:
    - authenticated user
    - file type
    - file size
    - permissions
        ↓
Server generates signed R2 upload URL
        ↓
Browser uploads directly to R2
        ↓
Browser notifies BLASTERR
        ↓
BLASTERR stores media metadata in Supabase
```

Do not allow arbitrary unauthenticated users to generate unlimited R2 upload URLs.
