# BLASTERR — PRELOADED BLAST SEEDING SYSTEM

I need you to add a **Preloaded Blast Seeding System** to the existing Blasterr platform.

IMPORTANT: The Blasterr platform is already built and functional. Do NOT rebuild the platform, replace the database, create a separate system, or disrupt existing functionality.

The purpose of this feature is to allow me to provide a curated list of major people, places, sports teams, brands, entertainment subjects, etc., and have the system automatically create the appropriate **canonical/preloaded Blast conversation** for each subject.

I want to be able to preload hundreds or thousands of carefully selected major subjects without manually creating each Blast through the UI.

---

# 1. CORE CONCEPT

Blasterr allows users to:

**Create a Blast about anything.**

That functionality must remain exactly as it currently works.

However, Blasterr will also have a curated collection of **Preloaded Blasts** for extremely high-profile subjects.

Examples:

* Donald Trump
* Los Angeles
* New York Knicks
* Los Angeles Lakers
* Taylor Swift
* LeBron James
* New York City
* Dallas Cowboys
* etc.

When a user searches for one of these subjects, Blasterr should route the user to the existing canonical/preloaded Blast rather than encouraging them to create a duplicate Blast for that same subject.

The preloaded Blast is essentially the **already-existing conversation starter** for that subject.

---

# 2. DO NOT TURN EVERYTHING INTO A PRELOADED BLAST

This is extremely important.

Preloaded Blasts are NOT intended for every possible subject.

They are reserved for the **top echelon of globally or nationally recognizable subjects**.

Potential categories:

* Major public figures
* Major celebrities
* Major athletes
* Major sports teams
* Major cities
* Major landmarks
* Major companies/brands
* Major entertainment properties
* Major events
* Other extremely high-interest subjects

Normal users must still be able to create new Blasts about anything that isn't preloaded.

---

Inspect the existing database and reuse the existing Blast/post architecture.

Do NOT create a completely separate content system unless absolutely necessary.

The existing normal Blast functionality must continue to work.

---

# 5. MAKE THE SEEDING PROCESS IDEMPOTENT

This is extremely important.

I must be able to run the preload process multiple times without creating duplicates.

For example:

First run:

Donald Trump → creates 1 canonical Blast

Second run:

Donald Trump → detects existing canonical Blast → does NOT create another

Third run:

Donald Trump → still only 1 canonical Blast

The system should identify existing records using a reliable unique identifier such as:

* canonical subject ID
* normalized slug
* unique subject key
* existing database ID

Do NOT rely solely on the display name.

---

# 6. PRELOADED BLAST CREATION

When the seed process runs, it should:

1. Read the curated subject list.
2. Normalize each subject.
3. Check whether that subject already has a canonical/preloaded Blast.
4. If it exists, leave it alone.
5. If it doesn't exist, create the canonical/preloaded Blast.
6. Associate the correct category/type.
7. Create aliases/search terms.
8. Add image/logo if the existing platform supports it.
9. Mark the Blast as preloaded/canonical.
10. Make it available through existing Blasterr search/discovery functionality.

Do not create fake user engagement.

Do NOT generate fake:

* likes
* comments
* views
* followers
* users
* reactions
* activity

The preloaded Blast should start legitimately with zero user engagement unless real activity exists.

---

Determine how the existing Blasterr architecture handles Blast ownership.

If every Blast requires a creator, use the existing appropriate system for an administrative/system-created Blast.

Do not create a fake human user account such as:

"Blasterr Admin"

unless the existing architecture specifically requires it and there is already an appropriate system/admin account architecture.

Prefer a system/canonical ownership mechanism if possible.

The user should understand that this is a Blasterr-provided conversation, not a fake user pretending to be a person.

# 9. PREVENT DUPLICATE MAJOR-SUBJECT BLASTS

When a user attempts to create a Blast about a subject that has a preloaded canonical Blast, the existing Create Blast flow should be enhanced rather than replaced.

Example:

User begins typing:

"Donald Trump"

The system recognizes the preloaded subject.

Display something similar to:

[🔥 JOIN EXISTING BLAST]

The user can then add their contribution to that existing Blast.

Do not prevent users from creating unrelated Blasts that merely mention the same person.

The system needs to distinguish between:

"I want to Blast Donald Trump."

and:

"I went to a restaurant in Los Angeles and had the worst burger."

The second should NOT automatically be forced into the Los Angeles canonical Blast unless the user's intent indicates that Los Angeles itself is the subject.

Avoid overly aggressive automatic matching.
