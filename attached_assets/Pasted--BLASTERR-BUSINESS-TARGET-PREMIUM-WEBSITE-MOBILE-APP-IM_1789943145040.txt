# BLASTERR BUSINESS TARGET PREMIUM — WEBSITE + MOBILE APP IMPLEMENTATION

## IMPORTANT — EXISTING PLATFORM

BLASTERR is an existing, functioning website and mobile app.

DO NOT rebuild, redesign, remove, replace, or refactor existing BLASTERR functionality.

DO NOT change existing user profiles, Blast creation, feeds, comments, reactions, Reblasts, notifications, authentication, search, Business Targets, Business Center, Admin functionality, or existing mobile navigation unless specifically required to connect this feature.

This is an ADDITIVE feature.

Before making changes:

1. Inspect the existing BLASTERR codebase.
2. Inspect the existing Business Target / Business Profile architecture.
3. Inspect the existing Business Center.
4. Inspect the existing subscription/payment architecture.
5. Inspect existing user/business authentication and authorization.
6. Inspect existing notification architecture.
7. Inspect existing analytics architecture.
8. Inspect existing Admin dashboard.
9. Identify reusable components and database tables.
10. Extend existing systems rather than creating duplicate systems.

The final implementation must work consistently on:

* BLASTERR website
* BLASTERR mobile app
* Existing Business Target pages
* Existing Business Center
* Existing Admin dashboard

# 24. ACCESS CONTROL

Premium feature access must be verified server-side.

DO NOT rely only on frontend checks.

Create a reusable subscription entitlement check such as:

`hasBusinessProAccess(businessTargetId, userId)`

The server must verify:

1. User is authenticated.
2. User has authorized access to the Business Target.
3. Business Target is associated with the user/business account.
4. Subscription is active or otherwise eligible under the configured trial/grace rules.

Protect all Business Center routes and premium API endpoints.
