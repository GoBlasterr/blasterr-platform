# 2. GOOGLE PLACES API

Use Google's current **Places API** through a secure server-side integration.

Do NOT scrape Google Maps.

Do NOT automate browser scraping of Google Maps.

Do NOT expose the Google API key to the client.

Store the API key securely using Replit Secrets / environment variables.

Suggested environment variable:

GOOGLE_PLACES_API_KEY

If a Google Maps Platform project does not already exist, create clear setup instructions for the administrator rather than hardcoding credentials.

---

# 3. GOOGLE DATA POLICY REQUIREMENT

Design the system around Google's current Places API policies.

IMPORTANT:

Do not treat Google Places data as BLASTERR-owned permanent business data.

Use Google as the external discovery/identity source.

Store the Google Place ID as the durable external identifier.

Store only the fields permitted under the applicable Google Maps Platform terms/policies.

Where Google Places data is displayed, implement the required Google attribution.

If Google data needs to be refreshed, retrieve it from the API rather than relying indefinitely on stale cached Places content.

Do not scrape Google Maps.

Do not copy Google reviews into BLASTERR.

Do not copy Google ratings into BLASTERR unless the applicable Google terms explicitly permit the intended use.

Do not copy Google photos into permanent BLASTERR storage unless the applicable API terms permit it.

Business-specific BLASTERR data must remain separate from Google Places data.
