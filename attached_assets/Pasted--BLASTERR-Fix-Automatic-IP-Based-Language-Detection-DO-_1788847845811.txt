## THE BUG

Automatic language detection is **not working for any country**.

Changing the visitor's IP address to different countries does not change the website language. The website always stays in the default language.

---

## WHAT I NEED

Implement or repair the existing **IP → Country → Language** detection so it works for **all visitors**.

### Required flow

Visitor opens **goblasterr.com**

↓

Detect the visitor's **real public IP address**.

↓

Resolve the IP to the visitor's **country**.

↓

Map the country to the correct language.

↓

Render the existing BLASTERR interface in that language automatically.

No popup.

No language selection screen.

No manual switching required.

## COUNTRY → LANGUAGE BEHAVIOR

The website must automatically change language based on the visitor's country.

Examples:

* English-speaking countries → English.
* France → French.
* Spain → Spanish.
* Germany → German.
* Italy → Italian.
* Portugal & Brazil → Portuguese.
* Netherlands → Dutch.
* Turkey → Turkish.
* Russia → Russian.
* China → Simplified Chinese.
* Japan → Japanese.
* South Korea → Korean.
* Arabic-speaking countries → Arabic (with RTL support).

If a country is not mapped, automatically fall back to English.

## IMPORTANT IMPLEMENTATION RULES

* Detect location using the visitor's **public IP address**, not a hardcoded value.
* Do not rely only on browser language, timezone, cookies, or account country.
* Perform detection before the page renders where possible so users see the correct language immediately.
* Cache the detected language safely without preventing updates when a visitor's IP location changes.
