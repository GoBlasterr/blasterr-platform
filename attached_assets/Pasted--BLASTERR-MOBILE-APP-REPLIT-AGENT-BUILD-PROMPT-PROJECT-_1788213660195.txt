# 10. CLOUDflare R2 MEDIA ARCHITECTURE

If Cloudflare R2 is currently being used by Blasterr:

The mobile app must NOT contain:

* R2 secret keys
* R2 access keys
* Private credentials

The mobile application should communicate with the Blasterr backend to obtain secure upload authorization/presigned URLs where appropriate.

Recommended flow:

1. User selects media.
2. Mobile app requests upload authorization from Blasterr backend.
3. Backend validates authenticated user.
4. Backend generates secure upload URL.
5. Mobile app uploads media directly to R2.
6. Backend records the resulting media URL/key.
7. Database associates the media with the user's Blasterr content.
8. Website and mobile app retrieve the same media.

Make the system resilient to:

* Failed uploads
* Large files
* Slow networks
* Interrupted uploads
* Duplicate uploads
* Invalid files
